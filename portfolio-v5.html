02 — PROCESS

Data in,
decisions out.

Every project starts the same way: understand what's happening before deciding what to change.

1
LISTEN TO THE DATA
User interviews, session recordings, support queries and operational pain points. What are people actually doing vs what we assumed?
2
SET THE BASELINE
If we can't measure the current state, we can't prove the next one is better. Pick the KPI before picking up Figma.
3
FRAME THE DECISION
Not "what should this screen look like" but "what job does this screen need to do?" Jobs-to-be-done, not feature lists.
4
TEST THE RISK
Prototype the riskiest assumption first via usability testing — not the full flow, just the part that could be wrong.
5
SHIP + WATCH
Track the metric we set in step 2. If it doesn't move, we go back to step 1.
